herdr-sessions

A Claude Code plugin for working inside Herdr: from one session, open another Claude Code session in a split or a tab, or find the sessions already running and talk to them. It works in both the Herdr app (`herdr-app` + `hc`) and the Herdr TUI (`herdr`), and works out which one it's in on its own.

plugin install herdr-sessions@longthread Changelog →

Reference

Use

Start your message with one of three triggers:

trigger what you get
pane: <what you want> one new Claude Code session in a visible split beside this one, started with a self-contained prompt; your focus stays put
tab: <what you want> the same, in a new background tab in this session's space
sessions: <what you want> Claude finds the matching session(s) by space, tab, folder or name, reads them, messages them, and reports back

Add details in plain words: "pane: below, run the tests in it", "tab: in ~/other-repo, name it docs".

Nothing happens without a trigger. Claude never opens sessions to parallelize its own work or in place of sub-agents. The one exception is a slash command or skill you invoke that itself says to open, close or message panes: that counts as the trigger for exactly those steps.

How it works

One SessionStart hook. Outside Herdr it prints nothing. Inside, it adds a short set of rules (rules.md) and says which manual to read:

detected by Herdr manual Claude reads on the first trigger
HERDR_ENV=1 and HERDR_PANE_ID TUI the herdr skill (installed by herdr integration install claude), then herdr <group> help
HC_TERMINAL_ID app herdr-app --skill for panes and tabs, hc --skill for sessions

The TUI is checked first: a TUI started inside an app terminal inherits HC_TERMINAL_ID too.

The plugin carries no Herdr command syntax. Herdr changes often and ships version-matched manuals, so the plugin holds only what the manuals can't know: when to act, what each trigger must produce (e.g. pane: is a visible split, not a background child), and guardrails — target this session's own pane, never answer another session's permission prompt, never kill or close what it didn't create, ask when a match is ambiguous.
